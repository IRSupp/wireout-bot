# راهنمای نصب و رفع اشکال WireOut Bot

ربات WireOut برای فروش و تمدید اکانت VPN و مدیریت کاربران استفاده می‌شود. برای راه‌اندازی ربات، **توکن تلگرام و لایسنس معتبر** لازم است. اجنت WireGuard فقط برای مدیریت سرورهای WireGuard از طریق API کاربرد دارد و نصب آن برای سایر روش‌های اتصال الزامی نیست.

| سرویس | ایمیج Docker Hub |
| --- | --- |
| ربات و پنل وب | [`boroumandhosein/wireout-bot:1.1.0`](https://hub.docker.com/r/boroumandhosein/wireout-bot) |
| اجنت WireGuard | نصب مستقیم از سورس GitHub روی میزبان، با سرویس `systemd` |

ایمیج ربات عمومی است و دریافت آن به ورود به Docker Hub نیاز ندارد. اجنت در این روش داخل Docker اجرا نمی‌شود. عمومی بودن ایمیج ربات به معنی رایگان بودن لایسنس نیست.

## ۱. پیش‌نیازها

- سرور لینوکس با معماری **AMD64 / x86_64**؛ نسخهٔ آزمایش‌شده Ubuntu 24.04 است.
- دسترسی `root` یا `sudo`.
- Docker Engine، افزونهٔ Docker Compose نسخهٔ **2.30 یا جدیدتر** و Python نسخهٔ **3.11 یا جدیدتر**.
- دسترسی اینترنت به Docker Hub، تلگرام، سرویس لایسنس و سرورهای VPN.
- توکن ربات از BotFather، آیدی عددی مدیر و لایسنس تهیه‌شده از فروشنده.

برای بررسی نسخه‌ها:

```bash
uname -m
docker --version
docker compose version
python3 --version
```

نصاب ربات روی Ubuntu 24.04، در صورت نبودن Docker یا Python، پیش‌نیازها را خودکار نصب می‌کند. نصب جدید Docker شامل Docker Compose نیز می‌شود و سرویس Docker خودکار راه‌اندازی می‌شود. نصب Docker موجود حذف یا جایگزین نمی‌شود. برای نصب دستی Docker از [راهنمای رسمی Ubuntu](https://docs.docker.com/engine/install/ubuntu/) استفاده کنید.

## ۲. نصب ربات

با SSH وارد سرور شوید و این دستور را اجرا کنید:

```bash
curl -fsSL https://raw.githubusercontent.com/IRSupp/wireout-bot/main/install.sh | sudo bash
```

نصاب فایل‌های موردنیاز را از GitHub در `/opt/wireout` قرار می‌دهد، پیش‌نیازهای نصب‌نشده را روی Ubuntu 24.04 به‌صورت خودکار نصب می‌کند و ربات را از Docker Hub دریافت می‌کند. فایل ZIP لازم نیست. اگر `curl` نصب نیست، ابتدا `sudo apt update && sudo apt install -y curl` را اجرا کنید.

این دستور باید در ترمینال تعاملی SSH اجرا شود. فایل تنظیمات نصب قبلی را بازنویسی نمی‌کند. دستورهای مدیریت بعدی را از پوشهٔ `/opt/wireout` اجرا کنید.

نصاب به زبان انگلیسی این اطلاعات را دریافت می‌کند:

| پرسش نصاب | مقدار موردنیاز |
| --- | --- |
| Docker image | مقدار پیش‌فرض `boroumandhosein/wireout-bot:1.1.0` را نگه دارید. |
| Telegram bot token | توکن ربات از BotFather |
| Owner Telegram numeric ID | آیدی عددی مدیر؛ برای چند مدیر، آیدی‌ها را با کاما جدا کنید. |
| License key | لایسنس ربات |
| Web admin username | نام کاربری پنل |
| Web admin password | رمز پنل، حداقل ۱۲ کاراکتر |
| Web panel port | پورت پنل؛ پیش‌فرض `8080` |

هنگام ورود رمز و توکن، نمایش ندادن کاراکترها طبیعی است. کلید رمزنگاری، رمز دیتابیس و شناسهٔ پایدار لایسنس به‌صورت خودکار ساخته می‌شوند.

### فعال‌سازی لایسنس

اگر لایسنس نیاز به اتصال به دستگاه داشته باشد، مقدار **License device ID** نمایش‌داده‌شده را به فروشنده بدهید. اگر نصب به دلیل فعال نبودن لایسنس متوقف شد، تنظیمات ذخیره شده‌اند؛ آن‌ها را حذف نکنید و دوباره نصب نکنید.

پس از فعال‌سازی، در صورت نیاز `LICENSE_KEY` را در `app.env` اصلاح کرده و از پوشهٔ نصب اجرا کنید:

```bash
sudo bash manage.sh start
sudo bash manage.sh status
```

در پایان، به ربات تلگرام پیام `/start` بفرستید. سپس سرورها و پلن‌های موردنظر را در ربات یا پنل تنظیم کنید.

## ۳. ورود به پنل وب

پنل با **IP عمومی سرور و پورت انتخابی هنگام نصب** باز می‌شود. اگر پورت پیش‌فرض را نگه داشته‌اید، در مرورگر این آدرس را باز کنید:

```text
http://YOUR_SERVER_IP:8080
```

به‌جای `YOUR_SERVER_IP`، آدرس IP سرور خودتان را بگذارید. اگر پورت دیگری انتخاب کرده‌اید، عدد `8080` را هم عوض کنید. برای ورود از نام کاربری و رمز پنلی که هنگام نصب تعیین کرده‌اید استفاده کنید؛ نیازی به تونل SSH نیست.

پورت انتخابی باید در فایروال سرور و فایروال پنل سرویس‌دهنده قابل دسترسی باشد. اگر UFW فعال است و پورت شما 8080 است، قانون متناظر این است:

```bash
sudo ufw allow 8080/tcp
```

اگر سرور پشت روتر است، هدایت پورت نیز باید تنظیم شده باشد. Docker ممکن است پورت منتشرشده را خارج از قواعد معمول UFW مسیریابی کند؛ برای محدودکردن دسترسی، فایروال سرویس‌دهنده یا قواعد سازگار با Docker را تنظیم کنید.

برای اتصال رمزنگاری‌شده، دامنه و reverse proxy با HTTPS تنظیم کنید. HTTP اطلاعات ورود را رمزنگاری نمی‌کند. خود کانتینر ربات نصب یا تمدید گواهی SSL را انجام نمی‌دهد.

### اگر با نصاب قبلی نصب کرده‌اید

در پوشهٔ نصب، فایل `compose.yaml` را باز کنید و در بخش `web`، مقدار `ports` را به این مقدار تغییر دهید:

```yaml
    ports:
      - '0.0.0.0:${WEB_PORT:-8080}:8080'
```

سپس فقط کانتینر پنل را بازسازی کنید:

```bash
cd /opt/wireout
sudo docker compose --env-file install.env up -d --no-deps --force-recreate web
```

اگر مسیر نصب شما متفاوت است، به همان پوشه بروید. این تغییر نیازی به نصب دوبارهٔ ربات، حذف دیتابیس یا تغییر توکن و لایسنس ندارد.

## ۴. نصب اجنت WireGuard — مستقیم روی سرور

اجنت با Python و `systemd` روی **خود سرور WireGuard** اجرا می‌شود و برای آن Docker لازم نیست. WireGuard باید از قبل نصب شده، اینترفیس آن فعال و فایل تنظیماتش موجود باشد. اجنت VPN، NAT یا اینترفیس جدید نمی‌سازد.

برای نمونه، اگر اینترفیس `wg0` است:

```bash
sudo wg show wg0
sudo test -f /etc/wireguard/wg0.conf
```

پیش از نصب، از تنظیمات WireGuard یک بکاپ خصوصی بگیرید. سپس این دستور را در ترمینال SSH سرور WireGuard اجرا کنید:

```bash
curl -fsSL https://raw.githubusercontent.com/IRSupp/wireout-bot/main/agent/install.sh | sudo bash
```

پیش‌نیازهای اجنت: `curl`، Python 3، ابزارهای `wg` و `wg-quick` و یک سیستم دارای `systemd`. نصاب این موارد را بررسی می‌کند و این اطلاعات را می‌پرسد:

| پرسش نصاب | مقدار |
| --- | --- |
| Existing WireGuard interface | نام اینترفیس موجود؛ پیش‌فرض `wg0` |
| Agent bind IPv4 address | آدرس خود سرور که اجنت روی آن گوش می‌دهد؛ پیش‌فرض `127.0.0.1` |
| Agent TCP port | پورت اجنت؛ پیش‌فرض `8787` |

توکن امن به‌صورت خودکار ساخته می‌شود. فایل‌ها در `/opt/wireout-wg-agent` قرار می‌گیرند و سرویس `wireout-wg-agent` فعال می‌شود. نصاب پس از راه‌اندازی، سلامت اجنت را هم بررسی می‌کند. اگر بررسی سلامت شکست بخورد، سرویس متوقف و تنظیمات برای عیب‌یابی نگه داشته می‌شوند.

### معرفی اجنت به ربات

توکن را به‌صورت خصوصی ببینید:

```bash
sudo cat /opt/wireout-wg-agent/agent.env
```

در تنظیمات سرور WireGuard داخل ربات، روش مدیریت **API** را انتخاب کنید:

- **URL:** آدرس اجنت که از شبکهٔ ربات قابل دسترسی باشد.
- **Token:** مقدار `WG_AGENT_TOKEN` در فایل بالا.

برای reverse proxy روی همان میزبان، bind روی `127.0.0.1` مناسب است. برای شبکهٔ خصوصی، آدرس خصوصی خود سرور را هنگام نصب وارد کنید. برای اتصال از اینترنت، از HTTPS پشت reverse proxy یا تونل رمزنگاری‌شده استفاده کنید؛ HTTP به‌تنهایی توکن را رمزنگاری نمی‌کند. دسترسی را به سرور ربات محدود کنید.

**نکته:** ربات داخل Docker است؛ `127.0.0.1` از دید ربات به خود کانتینر اشاره می‌کند، نه میزبان اجنت. حتی روی یک سرور مشترک، URL باید از کانتینر ربات قابل دسترسی باشد.

### مدیریت اجنت

```bash
# وضعیت
sudo systemctl status wireout-wg-agent --no-pager

# لاگ
sudo journalctl -u wireout-wg-agent -n 100 --no-pager

# راه‌اندازی مجدد، مثلاً بعد از ویرایش agent.env
sudo systemctl restart wireout-wg-agent

# توقف
sudo systemctl stop wireout-wg-agent
```

نصاب روی نصب قبلی بازنویسی نمی‌کند. هنگام ارتقا، از فایل‌های اجنت و `/etc/wireguard` بکاپ بگیرید، فایل `agent.py` نسخهٔ موردنظر را جایگزین کنید، `agent.env` را نگه دارید و سرویس را ری‌استارت کنید. نام اینترفیس و توکن را بدون هماهنگی با تنظیمات ربات تغییر ندهید.

اگر نسخهٔ Docker اجنت را قبلاً راه انداخته‌اید، پیش از نصب مستقیم آن را متوقف کنید:

```bash
sudo docker stop wireout-wg-agent
```

فایل تنظیمات WireGuard را حذف نکنید. پس از نصب مستقیم، توکن جدید را در ربات ثبت کنید. دو اجنت نباید هم‌زمان یک اینترفیس را مدیریت کنند. اگر قبلاً سرویس systemd نصب داشته‌اید، از مسیر ارتقا استفاده کنید؛ نصب مجدد لازم نیست.

## ۵. مدیریت و پشتیبان‌گیری ربات

دستورهای زیر را از پوشهٔ نصب ربات اجرا کنید:

| کار | دستور |
| --- | --- |
| وضعیت سرویس‌ها | `sudo bash manage.sh status` |
| مشاهدهٔ لاگ زنده | `sudo bash manage.sh logs` |
| بررسی لایسنس | `sudo bash manage.sh license` |
| توقف ربات و پنل | `sudo bash manage.sh stop` |
| راه‌اندازی | `sudo bash manage.sh start` |
| اعمال تغییرات تنظیمات | `sudo bash manage.sh restart` |
| گرفتن بکاپ | `sudo bash manage.sh backup` |

بکاپ ربات در پوشهٔ `backups` ذخیره می‌شود و شامل دیتابیس و تنظیمات محرمانه است. یک نسخهٔ امن خارج از سرور نگه دارید. تنظیمات WireGuard و فایل `agent.env` را نیز جداگانه پشتیبان بگیرید.

فایل‌های `app.env` و `install.env` را حذف نکنید. به‌خصوص **FERNET_KEY** باید با دیتابیس مطابقت داشته باشد و **HARDWARE_ID** باید هنگام ارتقا ثابت بماند. دستور `docker compose down -v` می‌تواند داده‌های دیتابیس را حذف کند.

### به‌روزرسانی

ابتدا بکاپ بگیرید، سپس ربات را متوقف کنید. ایمیج نسخهٔ جدید اعلام‌شده توسط فروشنده را دریافت کنید و فقط `WIREOUT_IMAGE` را در `install.env` تغییر دهید. بعد `sudo bash manage.sh start` را اجرا و وضعیت و لاگ‌ها را بررسی کنید. بدون بررسی سازگاری دیتابیس، به نسخهٔ قدیمی برنگردید.

## ۶. رفع مشکلات رایج

| مشکل | بررسی و راه‌حل |
| --- | --- |
| خطای `exec format error` | خروجی `uname -m` را بررسی کنید. این نسخه برای AMD64 است، نه ARM. |
| خطا دربارهٔ `format: raw` | Docker Compose باید نسخهٔ 2.30 یا جدیدتر باشد. این گزینه را حذف نکنید؛ برای حفظ صحیح رمزها استفاده می‌شود. |
| دریافت ایمیج ناموفق است | نام ایمیج، DNS، دسترسی HTTPS به Docker Hub و محدودیت دریافت را بررسی کنید. |
| توکن تلگرام تأیید نمی‌شود | توکن را در BotFather بررسی کنید و از دسترسی سرور به تلگرام مطمئن شوید. |
| خطای تلگرام `Conflict` یا `getUpdates` | یک نمونهٔ دیگر با همان توکن فعال است. نمونهٔ قبلی را متوقف کنید. |
| خطای لایسنس | `manage.sh license` را اجرا کنید؛ فعال‌سازی، تاریخ اعتبار، اتصال اینترنت و ساعت سرور را بررسی کنید. شناسهٔ دستگاه را تغییر ندهید. |
| ورود پنل موفق است ولی صفحات خطای 403 دارند | ورود مدیر، الزام لایسنس معتبر را دور نمی‌زند. وضعیت لایسنس را بررسی کنید. |
| پنل با IP عمومی باز نمی‌شود | IP و پورت را بررسی کنید؛ وضعیت سرویس web، فایروال سرویس‌دهنده و هدایت پورت روتر را بررسی کنید. اگر با نسخهٔ قبلی نصب کرده‌اید، بخش «اگر با نصاب قبلی نصب کرده‌اید» را انجام دهید. |
| سرویس `init` متوقف است | اگر با کد صفر پایان یافته، طبیعی است؛ این سرویس فقط دیتابیس را آماده می‌کند. |
| خطای اتصال دیتابیس | لاگ سرویس `db` را بررسی کنید. رمز داخل `DATABASE_URL` باید با رمز واقعی دیتابیس مطابقت داشته باشد. تغییر `DB_PASSWORD`، رمز دیتابیس موجود را خودکار عوض نمی‌کند. |
| رمز سرورها قابل خواندن نیست | کلید `FERNET_KEY` اصلیِ همان دیتابیس را بازیابی کنید. کلید جدید اطلاعات قبلی را رمزگشایی نمی‌کند. |
| اجنت خطای 401 می‌دهد | توکن ثبت‌شده در ربات با `WG_AGENT_TOKEN` یکسان نیست. پس از ویرایش فایل env، سرویس `wireout-wg-agent` را ری‌استارت کنید. |
| اجنت در دسترس نیست | آدرس bind، پورت، فایروال و مسیر شبکه از کانتینر ربات را بررسی کنید. `127.0.0.1` کانتینر با میزبان متفاوت است. |
| خطای `address already in use` | سرویس دیگری، احتمالاً اجنت قدیمی، پورت را گرفته است. مالک پورت را مشخص و جابه‌جایی را هماهنگ کنید. |
| اجنت خطای 500 یا خطای اینترفیس دارد | نام اینترفیس، خروجی `wg show`، اجرای سرویس با دسترسی root و فایل تنظیمات WireGuard را بررسی کنید. |
| peer پس از ری‌استارت ناپدید می‌شود | وضعیت `persistent`، دسترسی نوشتن به `/etc/wireguard` و خطاهای ذخیره‌سازی را بررسی کنید. تغییر زنده بدون ذخیره کافی نیست. |
| پیام پایان حجم یا زمان دیر می‌رسد | لاگ ربات، ارتباط تلگرام، مسدود نکردن ربات توسط کاربر و موفقیت دریافت آمار از سرور VPN را بررسی کنید. خطاهای موقت ارسال دوباره تلاش می‌شوند. |
| تمدید SSL پشت VPN یا روتر شکست می‌خورد | DNS عمومی، مسیر ورودی و port forwarding متناسب با روش اعتبارسنجی گواهی را بررسی کنید. تمدید SSL وظیفهٔ سرویس پراکسی/گواهی میزبان است. |

برای بررسی اولیهٔ ربات:

```bash
sudo bash manage.sh status
sudo docker compose --env-file install.env logs --tail 100 bot web db
df -h
timedatectl status
```

اگر هنگام خرید، سرویس ناگهان قطع شد، پیش از تکرار عملیات، تراکنش کیف پول و حساب ساخته‌شده روی سرور VPN را بررسی کنید تا خرید یا برداشت تکراری ایجاد نشود.

## ۷. ارسال گزارش مشکل

نسخهٔ ایمیج، معماری سرور، نسخهٔ Docker و Compose، زمان خطا، کاری که انجام داده‌اید و متن خطای **پاک‌سازی‌شده از اطلاعات محرمانه** را ارسال کنید.

توکن تلگرام، لایسنس، توکن اجنت، فایل‌های env، بکاپ دیتابیس و کلید خصوصی WireGuard را در Issue عمومی GitHub قرار ندهید. برای موارد حاوی اطلاعات مشتری یا دسترسی، از مسیر خصوصی پشتیبانی فروشنده استفاده کنید.
